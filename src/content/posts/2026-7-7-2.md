# 如何使用 Cloudflare Tunnel 做内网穿透（免备案、免公网 IP）

在国内搭建个人服务时，经常会遇到两个痛点：**没有公网 IP**（运营商 NAT 转发）和**域名需要备案**（国内机房强制要求）。Cloudflare Tunnel（原名 Argo Tunnel）可以同时解决这两个问题。

本文将以 Ubuntu Server 为例，带你从零开始配置 Cloudflare Tunnel。

## 一、什么是 Cloudflare Tunnel

Cloudflare Tunnel 会在你的本地服务器和 Cloudflare 全球边缘网络之间建立一条加密隧道。外部用户访问你的域名时，流量会经过 Cloudflare 的 CDN 节点，再通过隧道转发到你的本地服务。

**核心优势：**

- **无需公网 IP**：家庭宽带、学校内网、NAT 环境均可使用
- **免备案**：域名通过 Cloudflare 代理，走海外节点
- **自带 HTTPS**：Cloudflare 自动签发 SSL 证书
- **隐藏真实 IP**：外部无法直接获取源服务器 IP
- **免费**：Cloudflare 免费套餐即可使用

## 二、准备工作

### 前提条件

| 项目 | 要求 |
| :--- | :--- |
| **域名** | 一个自己的域名，且 DNS 托管在 **Cloudflare** |
| **服务器** | 任意能上网的 Linux 机器（内网即可） |
| **Cloudflare 账号** | 免费注册即可 |

> 如果你还没有域名，推荐在 [Cloudflare Registrar](https://www.cloudflare.com/products/registrar/) 直接注册购买，省去转移 DNS 的步骤。

### 将域名 DNS 托管到 Cloudflare

1. 注册并登录 [Cloudflare](https://dash.cloudflare.com/)
2. 点击「添加站点」，输入你的域名
3. 选择 Free 套餐，按提示将域名的 Nameserver 修改为 Cloudflare 提供的地址
4. 等待 DNS 生效（通常几分钟到几小时）

## 三、安装 cloudflared

`cloudflared` 是 Cloudflare Tunnel 的客户端程序，安装在你需要穿透的服务器上。

### 方式一：使用包管理器安装（推荐）

```bash
# 添加 Cloudflare 官方 GPG 密钥
sudo mkdir -p --mode=0755 /usr/share/keyrings
curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null

# 添加 apt 源
echo 'deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main' | sudo tee /etc/apt/sources.list.d/cloudflared.list

# 安装
sudo apt update
sudo apt install cloudflared -y
```

### 方式二：手动下载二进制文件

```bash
# 下载最新版本（以 amd64 为例）
wget https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64
sudo mv cloudflared-linux-amd64 /usr/local/bin/cloudflared
sudo chmod +x /usr/local/bin/cloudflared
```

验证安装：

```bash
cloudflared --version
```

## 四、创建 Tunnel

### 1. 登录 Cloudflare

```bash
cloudflared tunnel login
```

执行后会输出一个 URL，在浏览器中打开，选择你要使用的域名完成授权。授权成功后，证书文件会自动保存到 `~/.cloudflared/cert.pem`。

### 2. 创建隧道

```bash
cloudflared tunnel create my-tunnel
```

`my-tunnel` 是隧道名称，可以自定义。执行后会输出隧道 ID，同时会在 `~/.cloudflared/` 目录下生成对应的凭证文件。

查看隧道列表：

```bash
cloudflared tunnel list
```

### 3. 配置 DNS 路由

为隧道绑定一个子域名，让外部可以通过该域名访问你的服务。假设你想用 `mc.example.com` 访问本地 Minecraft 服务器：

```bash
cloudflared tunnel route dns my-tunnel mc.example.com
```

> 执行后 Cloudflare 会自动在你的 DNS 记录中添加一条 CNAME 记录 `mc.example.com → <tunnel-id>.cfargotunnel.com`，无需手动操作。

## 五、编写配置文件

创建配置文件 `~/.cloudflared/config.yml`：

```bash
mkdir -p ~/.cloudflared
vim ~/.cloudflared/config.yml
```

填入以下内容：

```yaml
tunnel: my-tunnel                          # 隧道名称
credentials-file: /root/.cloudflared/my-tunnel.json  # 凭证文件路径（根据实际调整）

ingress:
  # 示例 1：Minecraft 服务器（TCP）
  - hostname: mc.example.com
    service: tcp://127.0.0.1:25565

  # 示例 2：Web 服务（HTTP）
  - hostname: web.example.com
    service: http://127.0.0.1:8080

  # 示例 3：Terraria 服务器（TCP）
  - hostname: terraria.example.com
    service: tcp://127.0.0.1:7777

  # 兜底规则：所有未匹配的请求返回 404
  - service: http_status:404
```

> **注意**：TCP 类型的隧道需要客户端也安装 `cloudflared` 才能访问。HTTP/HTTPS 类型的服务可以直接通过浏览器访问。

### 关键参数说明

| 参数 | 说明 |
| :--- | :--- |
| `tunnel` | 隧道名称，需与创建时一致 |
| `credentials-file` | 凭证文件的绝对路径 |
| `hostname` | 绑定的子域名 |
| `service` | 本地服务的协议和地址，如 `tcp://127.0.0.1:25565` |

## 六、启动与守护

### 方式一：前台运行（测试用）

```bash
cloudflared tunnel run my-tunnel
```

### 方式二：安装为系统服务（推荐生产环境）

```bash
sudo cloudflared service install
```

安装后 `cloudflared` 会自动读取 `~/.cloudflared/config.yml` 并注册为 systemd 服务。

```bash
# 启动服务
sudo systemctl start cloudflared

# 开机自启
sudo systemctl enable cloudflared

# 查看状态
sudo systemctl status cloudflared

# 查看日志
sudo journalctl -u cloudflared -f
```

## 七、验证测试

### HTTP 服务

浏览器直接访问 `https://web.example.com`，应能正常打开你的本地 Web 服务。

### TCP 服务（如 Minecraft）

客户端需要先安装 `cloudflared`，然后通过隧道连接：

```bash
# 在客户端机器上安装 cloudflared 后执行
cloudflared access tcp --hostname mc.example.com --url 127.0.0.1:25565
```

此时 Minecraft 客户端连接 `127.0.0.1:25565` 即可加入服务器。

## 八、常见问题排查

### 1. 隧道无法启动

- 检查 `config.yml` 中 `credentials-file` 路径是否正确
- 确认已执行 `cloudflared tunnel login` 完成授权
- 查看日志：`sudo journalctl -u cloudflared -f`

### 2. 域名无法访问

- 确认 DNS 记录已自动创建（在 Cloudflare 控制台 DNS 页面查看）
- 确认域名 DNS 托管已生效（NS 记录指向 Cloudflare）
- 对于 TCP 服务，确认客户端也安装了 `cloudflared`

### 3. 连接延迟高

- 免费套餐走的是 Cloudflare 全球 CDN，国内访问可能绕路
- 可尝试在 Cloudflare 控制台开启 Argo Smart Routing（付费功能）

### 4. 端口被占用

- 确保本地服务监听的是 `127.0.0.1` 而非 `0.0.0.0`，避免端口直接暴露在公网

## 九、进阶技巧

### 多服务共用一条隧道

在 `ingress` 中配置多个 `hostname` 规则即可，无需创建多条隧道。

### 搭配 Docker 使用

```yaml
# docker-compose.yml
services:
  cloudflared:
    image: cloudflare/cloudflared:latest
    command: tunnel run
    volumes:
      - ./cloudflared:/home/nonroot/.cloudflared
    restart: always
```

### 监控隧道状态

Cloudflare 控制台 → Zero Trust → Networks → Tunnels 可查看隧道运行状态、吞吐量等指标。
